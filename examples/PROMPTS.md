# Prompts for Cinematic Scroll

Start with the subject, supplied content, visitor action, and delivery format.
The skill chooses an implementation that fits; chapter counts, rendering tiers,
and pin distances are not prerequisites. Keep applicable brand instructions.

## Start here — a complete first page

> Use cinematic-scroll to build a one-page story for [PRODUCT / SUBJECT] using
> [LOCAL COPY AND ASSETS]. The visitor should understand [KEY IDEA] and then
> [ACTION / REAL DESTINATION]. Choose one signature transformation that explains
> the subject. Preserve this project's brand and stack; if there is no app, deliver
> standalone HTML. Make the first preview work without provider keys. Include a
> complete mobile and reduced-motion composition, inspect the browser result, and
> report the exact opening command and any checks that could not run.

## Subject-led example briefs

These are alternative briefs, not sections to combine into one page. Fictional
examples must be identified as concepts; do not invent evidence or real clients.

### Product mechanism

> Use cinematic-scroll to explain [PRODUCT] from the supplied diagram and copy.
> Let scroll separate its functional layers, then hold the labels while the visitor
> reads how they work together. Keep a useful static diagram on mobile and without
> JavaScript. Use SVG or CSS unless the supplied geometry needs real 3D. Link the
> closing action to [DESTINATION].

Study: [FIELD](v3-flagship/README.md) for a subject-specific control and fallback.
The mechanism and copy should come from the new product, not FIELD's optical theme.

### Creative portfolio

> Use cinematic-scroll to present these [PROJECT FILES] as a creative portfolio.
> Make the selected work the focal point. Let a contact sheet expand one project
> into its real case-study detail, preserving access to all other projects. Use my
> existing identity and contact destination. Keep touch and keyboard navigation
> equally useful; avoid decorative statistics and fabricated client logos.

Study: [Studio portfolio](studio/README.md). This example's name does not require
or imply use of the paid Studio edition.

### Editorial story

> Use cinematic-scroll to turn [ARTICLE AND IMAGES] into an editorial reading
> experience. Choose one image transition that reveals context the reader would
> otherwise miss. Keep body copy stable and selectable, preserve the article's
> meaning and order, and use restrained motion. Deliver in [EXISTING APP / HTML].

Study: [Renaissance](renaissance/README.md) for art direction; adapt the visual
language to the brief rather than copying its styling or number of chapters.

### Material study

> Use cinematic-scroll to build an interactive study of [SUPPLIED MATERIAL OR
> OBJECT]. Let a labeled control change lighting or reveal a real structural
> difference. Show the effect on the object itself. Include reset, keyboard
> control, and a useful still when rendering is unavailable. Explain any simulated
> behavior without making unsupported physical claims.

Study: [effects lab](effects-lab/README.md) for isolated runtime treatments.
A shader preset is an implementation option, not the subject of the story.

### Film or video reveal

> Use cinematic-scroll with [LOCAL VIDEO AND POSTER] to reveal [SUBJECT / CHANGE].
> Map scroll to a meaningful sequence, keep copy readable while seeking, and use
> the poster when playback or motion is unavailable. Inspect fast and reverse
> scrolling and report browser/device limitations actually observed.

Study: [KERN](kern-calibration/README.md) for video composition. Verify media
availability and seeking behavior before reusing its implementation assumptions.

## Existing app — one focused improvement

> Use cinematic-scroll to improve [ROUTE / COMPONENT] in this existing app.
> Inspect it first. Preserve the framework, styling, content, navigation, and useful
> interactions. Improve [SPECIFIC WEAK BEAT] with a visible subject-specific change.
> Reuse the current scroll clock and clean up owned effects on unmount. Show browser
> evidence of the changed scene, including its mobile and static equivalents.

## New Next.js site

> Use cinematic-scroll to build a new Next.js story for [SUBJECT], using the bundled
> template as a starting point. Read its instructions and copy the relevant source
> instead of reconstructing it from memory. Adapt the content and routes to this
> brief; choose only the chapters needed. Keep the first run usable without generated
> assets. Run the app's checks and browser proof, then give the preview command,
> customization locations, and verification limitations.

Asset generation is a separate optional step. For a provider workflow, read the
current bundled model/adapter instructions and specify the desired assets and budget.

## Storyboard only

> Use cinematic-scroll to plan a scroll story for [COPY / ASSETS]. No code yet.
> Describe the visitor's takeaway, one signature moment, and each beat's start,
> transformation, readable hold, and exit. Include mobile/static equivalents and
> explain how the closing action follows from the story.

## Audit and verification

> Use cinematic-scroll to audit [LOCAL BUILD / URL]. Inspect the opening, signature
> moment, transition midpoint, and closing action on desktop and narrow screens.
> Check keyboard interaction, reduced motion, missing enhancement, reverse scroll,
> and resize where relevant. Separate observed defects from design suggestions.
> Give a prioritized repair list; do not change the build for this audit.

> Use cinematic-scroll to fix and verify [LOCAL BUILD]. Repair observed defects,
> run the project's checks and browser evidence, and inspect the screenshots.
> A static doctor score or a comment in source is not performance proof. Report
> missing checks honestly and honor any required brand judge threshold.

## Companion skills

Two smaller skills ship beside `cinematic-scroll`. Use them before and after a build.

> Use launch-page-strategy to write the story brief for [PAGE] before any design.
> Read [SUPPLIED COPY AND PROOF], choose one primary action, map the top three
> objections to the sections that answer them, place each proof item beside its
> claim, and record what is still missing. Do not invent facts or promises.

> Use scroll-audit on [URL I OWN] and write remediation-plan.md. Score pacing,
> performance, accessibility and emotional arc, list the taste violations with
> evidence, and put the single highest-impact fix first. Say which checks could
> not run.

## Outside the skill's scope

Ordinary dashboards, unrelated button animations, and generic theme generation do
not need this skill. Storyboards, restrained cinematic pages, and integration into
non-Next.js apps are supported.
